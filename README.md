# 愚见者的故事书

一个跑在 Windows 窗口里的**通用文字冒险播放器**。它不挑题材——怪谈、日常、科幻、历史都行，
因为故事根本不在代码里：

- **剧情**写在 `stories\` 里的纯文本档案（`.txt`）里，分支就是一个个 `:: 节点名`；
- **图片**放在 `images\<档案名>\` 里，文件名用数字，故事里写 `@图片 1 小窗` 就能播；
- 改完在程序里按一下 `F5`，**不用重启、不用重新编译**，立刻看到新剧情。

```
十月三日   ·  20 个结局    ← 现在档案列表里就它一个
你的故事   ·  ？           ← 复制一份 _模板.txt 就能开始
```

## 目录结构

```
愚见者的故事书\
├── 愚见者的故事书.exe          程序本体（双击即玩）
├── main.cpp                    全部代码（Win32 + GDI+ 单文件）
├── stories\                    故事档案，一个档案 = 一个 .txt
│   ├── 十月三日.txt             你自己的故事
│   └── _模板.txt                带注释的空白模板（下划线开头不显示在列表里）
├── images\                     图片库，一个档案对应一个子文件夹
│   └── 十月三日\               文件名用数字：1.png 2.png 3.png ……
├── tools\
│   ├── 生成安装包.cmd            ← 双击这个，打包成一个 exe 发人
│   ├── pack_release.ps1         打包脚本本体
│   ├── launcher.cpp             自解压启动器源码
│   ├── launcher_stub.exe        启动器（打包时拼进去的"壳"）
│   └── 图片转PNG.ps1            （可选）命令行版图片转换，程序本身会自动转
├── 版本日志.txt                 每次打包追加一行，版本号就是这么来的
├── 版本.txt                     最近一次打包的版本号（程序会读它显示在界面上）
├── 存档.txt                     游玩进度（走位 / 数值 / 结局 / 流程图解锁情况）
├── 发布\                        打包产物：愚见者的故事书-v1.2.3.exe 这样按版本号命名
├── terminal_version.cpp        最初那版终端游戏（深夜便利店）的源码
│                               （想玩就编译成 main.exe，命令见下面）
└── README.md
```

## 三分钟，加一个你自己的故事

1. 复制 `stories\_模板.txt`，改名成比如 `我的故事.txt`；
2. 照着模板改 `@标题`、写节点、写选项；
3. 想配图就把图片放进 `images\我的故事\`，命名 `1.png`、`2.png`……；
4. 回到程序按一下 `F5`（重载），列表里就会出现它，点进去就能玩。

## 剧本语法

纯文本，UTF-8 最好（GBK 的旧文件也能读）。`#` 开头是注释，空行忽略。

| 写法 | 作用 |
| --- | --- |
**注释**：`#` 开头的整行（或 `//` 开头的整行）是注释，不参与运行；
**指令行**（`@`、`>`、`::`、`->` 开头）后面留一个空格再写 `# 说明` 或 `// 说明` 就是行尾注释，
不会被当成内容；**正文行里的 `#` 原样显示**，所以剧情里写 "# 3 号柜" 没问题。

| `@标题 十月三日` | 档案名，显示在列表和标题上 |
| `@开始 站台` | 从哪个节点开始，不写就用第一个节点 |
| `:: 节点名` | 开一个新节点（分支） |
| `@场景 第一幕 ｜ 末班车` | 插一行青色小标题 |
| `@图片 1 小窗` | 显示 `images\档案名\1.png`，小窗播放（上图下文） |
| `@图片 2 全屏` | 整窗铺满这张图，文字带半透明底框浮在图上 |
| `@图片 0` | 关掉图片 |
| `> 选项文字 -> 目标节点` | 一个选项按钮（`->` 也可以写成 `→`） |
| `-> 目标节点` | 没有选项，显示一个「继续 →」按钮 |
| `@结局 1 末班车 \| 结语` | 结局，暖黄色框显示，并计入结局收集进度 |
| `@数值 精神值 = 60` | 声明一个数值（像变量一样，写一次就够） |
| `@改变 精神值 -5` | 进入这个节点时数值自动变化 |
| `@摘要 走廊尽头那扇门` | 这个节点在流程图里的说明（建议 24 字内，每个节点都写） |

### 数值：让选项和分支受数值影响

在 `\|` 后面写「条件」或「效果」，条件和效果可以一起写，用逗号 / 分号隔开：

```
@数值 精神值 = 60
@数值 清醒度 = 0

:: 走廊
@摘要 走廊尽头那扇门
@改变 清醒度 +1
走廊很长。尽头的门底下漏着光。
> 推门进去 -> 门后 | 精神值 >= 40          # 不满足就不显示这个选项
> 喝口冷水 -> 走廊 | 精神值 +10, 清醒度 +1   # 选中后数值变化
> 把灯关了 -> 走廊 | 精神值 = 20            # 直接设成 20

:: 门后
@摘要 门后有一面镜子
@改变 精神值 -10
-> 镜子前 | 精神值 >= 30
-> 结局・崩掉                                # 不带条件 = 兜底
```

| 写法 | 含义 |
| --- | --- |
| `精神值 +10` / `精神值 += 10` | 加 10 |
| `精神值 -5` / `精神值 -= 5` | 减 5 |
| `精神值 = 30` | 直接设成 30 |
| `精神值 >= 50` | 条件是「大于等于 50」才有效 |
| `精神值 >= 50, 精神值 -5` | 条件 + 效果一起写 |

比较符有 `>=` `<=` `>` `<` `==` `!=`。写在选项后面 = 不满足就不显示这个选项；
写在 `->` 后面 = 条件跳转（从上往下试，第一条满足的生效，所以最后记得留一条不带条件的兜底）。

数值只有在该节点写了 @显示 的时候才会露出来，变化时会亮一下；每次到达节点时的数值都会被记进存档，流程图卡片上显示的就是**上次到这里时**的数值。
想看现成的写法，翻 `stories\_模板.txt` 或者自己写好的 `stories\十月三日.txt`。

### 选项反馈页（@反馈）

想让"选完 → 下一段"中间插一页反馈（不然数值变了玩家看不见，观感很跳），就在选项下面写 `@反馈`：

```
> 认真学习 -> 教室 | 学力 +1
@反馈 你认真听了一节课，学力涨到了 {学力}。
@反馈 同桌把笔记推过来一半。

> 趴在桌上睡了 -> 教室 | 精神值 +5
```

- **只有写了 `@反馈` 的选项才有这一页**：选中后先弹出反馈页，点「确认」（或点一下 / 空格）才进下一个节点；
- **没写就直接进下一个节点**，行为和以前一样；
- 反馈页上写什么完全由你决定：可以只写剧情，可以写 `{学力}` 把数值念出来，
  也可以故意什么都不提——**引擎不会自动列出"谁 +1 谁 -2"**，隐式的数值变化不会被暴露；
- `@反馈` 里的 `{...}` 是在**选项效果结算之后**展开的，所以显示的是变化后的值；
- 一页可以写多行 `@反馈`（就是多行文字），也可以写成一行 `@反馈 文字`。

### 画面卡（@画面）：黑屏大字 / 全屏图 / 渐显

想让故事开场（或某个转折点）先来一张黑屏大字，就在节点里写 `@画面`：

```
:: 开场
@画面 打字                  # 打字=逐字浮现；写「直接」就是一下全显示（默认）
@画面 十月三日              # 每条 @画面 就是大字的一行
@画面 七日轮回
@画面 -> 教室              # 可选：放完跳到「教室」

@摘要 开学第一天
你站在教室门口……
```

| 写法 | 作用 |
| --- | --- |
| `@画面 打字` | 开一张卡并逐字浮现（`逐字` / `typing` 同义） |
| `@画面 直接` | 开一张卡、文字一下全显示（不写关键字也是这个） |
| `@画面 一行文字` | 追加一行大字；字号按每行字数自动算 |
| `@画面 -> 目标节点` | 这张卡放完跳到那个节点 |
| `@画面 图片 3` | 这张卡改用 `images\档案名\3.png` **全屏铺满** |
| `@画面 图片 3 -> 走廊` | 图片卡放完跳转 |

要点：

- **不写 `->` 就是"只放一张画面"**：看完按任意键（或点一下）直接回到本节点正文继续，不改变流程、不改存档位置；
- **卡片的 `->` 就是本节点的出口**：节点里只写一条 `@画面 -> 目标` 就够，不用再补普通的 `-> 目标`；
  卡片写了 `->` 就一定跳走，本节点的正文和选项不再显示；
- 反过来，如果箭头写在**正文**里（`@画面` 下面单独一行 `-> 某节点`），卡片放完会先回到本节点正文——
  但如果这个节点的正文**一个字都没有**、又正好只有这一条不带条件的 `->`，引擎会**直接跳过去**，
  不会再弹一页空白让你点确认（正文里有字、有选项、有 @行动、或有多条带条件的 `->` 时，还是照常显示这一页）；
- 一个节点**一张卡**；想连续放两张，就把它拆成两个节点用 `->` 串起来；
- 黑屏会在 0.4 秒内淡入；底部固定显示 `[ 点击屏幕或按任意键继续 ]`（文字打完才出现）；
- 打字模式下按任意键/点击，**先补完当前文字**，再按一次才翻页，手快也不会把内容刷过去；
- 字号是自适应的：字少时按"标题"比例（不超过窗口高度的 12%），字多或行数多时自动再缩小，整块居中；
- 大字里也能用 `{}`：`@画面 第 {回合数} 天` 会显示成"第 3 天"；
- 进度条 / 侧栏在画面卡期间不显示，放完自动恢复。

### @摘要

流程图卡片上显示的就是这句话，建议 24 字以内。没写的话流程图里会用节点名代替，
并且列表页会提示「有 N 个节点没写 @摘要」——不影响玩，但流程图会不好认。

### 循环 / 重复的故事线

节点可以指回前面的节点形成环，数值会一路继承下来，"同一段来回重复几遍"是支持的：

```
@数值 经过次数 = 0

:: 值班室
@摘要 值班室（循环起点）
@改变 经过次数 +1
你又回到值班室。
> 再走一趟走廊 -> 走廊
> 坐下，不走了 -> 结局・停

:: 走廊
@摘要 走廊（循环中途）
@改变 精神值 -5
-> 值班室 | 经过次数 < 3
-> 结局・走出循环
```

- 每进一次 `值班室` 就执行一次 `@改变 经过次数 +1`，转几圈数值就累加几次；
- `-> 值班室 | 经过次数 < 3` 让环转三圈后自动跳出（条件跳转从上往下试）；
- 流程图里这种"回头路"会从卡片右侧绕上去，不会和正向的线重叠；环里的节点照样记录、照样能回溯；
- 回溯进环里的节点，数值会按**最后一次**经过它时的那份复原。想从头重走一遍环，
  就回溯到环外面那个节点。

### 数组（可以混着放数字和文字）

```
@数组 背包 = 面包, 咖啡, 3
```

| 写法 | 作用 |
| --- | --- |
| `@加 背包 手电筒` | 末尾加一个 |
| `@删 背包 面包` | 删掉第一个一样的 |
| `@删位 背包 0` | 按下标删（从 0 开始） |
| `@插 背包 0 火柴` | 插到指定下标 |
| `@清空 背包` | 清空 |
| `@数量 背包 -> 件数` | 把长度写进某个数值 |
| `@查找 背包 面包 -> 位置` | 找到写下标，找不到写 -1 |
| 条件写 `背包 含 面包` | 数组里有没有这个元素 |
| 正文写 `{背包}` / `{背包[0]}` | 整个数组 / 第几个元素 |

- 一个数组里可以混着放文字和数字（纯数字会自动识别，`@取`/`@数量` 这类地方能当数值用）；
- 元素可以带空格和标点，就是不能带换行；存进 `存档.txt` 时会自动转义；
- 数组和数值一样会存进存档，关掉再开还在。

### 封装节点：一个节点里装一套"小系统"（回合制战斗那种）

节点里只要写了 `@行动`，它就变成**封装节点**：

- 按钮点了**在本节点内执行**，不会在流程图上多出分支；
- `@回合` 里的流程在每个回合开头自动跑（敌人反击、判定死亡）；
- 出口用 `-> 目标 | 条件`，条件满足才离开这个节点；
- **只有写了 `@显示` 的数值 / 数组才会在侧栏出现**。

```
@数值 我方血量 = 30
@数值 敌方血量 = 24
@数值 回合数 = 0
@数值 伤害 = 0
@数值 反击 = 0

@数组 背包 = 面包, 咖啡
@数组 战报

:: 战斗
@摘要 和影子打起来
@显示 我方血量 条 30
@显示 敌方血量 条 24
@显示 回合数
@显示 背包 列表
@显示 战报 列表
@清空 战报
@加 战报 影子扑了上来。
它没有脸，却能听见你的呼吸。

@行动 挥拳
@骰 伤害 = 1d6+2
@改变 敌方血量 -伤害
@加 战报 你挥拳，打出 {伤害} 点。

@行动 喝咖啡 | 背包 含 咖啡
@删 背包 咖啡
@改变 我方血量 +8
@加 战报 你灌下咖啡，回了 8 点。

@行动 看一眼状态
@不耗回合
你数了数：还剩 {背包}。

@回合
@改变 回合数 +1
@骰 反击 = 1d4
@改变 我方血量 -反击
@加 战报 影子拍过来，你掉了 {反击} 点。

-> 结局・赢了 | 敌方血量 <= 0
-> 结局・倒下 | 我方血量 <= 0
```

几个要点：

- 侧栏在左上角，**小窗图片会自动让到右边**，互不遮挡；全屏图片时侧栏浮在图上。
- 血条写法 `@显示 血量 条 最大值`，最大值可以写数字，也可以写另一个数值名；低于 30% 会自动变红。
- `@行动` 的按钮能带条件（`@行动 喝咖啡 | 背包 含 咖啡`），东西用完了，按钮就自动消失。
- `@不耗回合` 让"查看状态"这类动作不推进回合。
- **语句后面也能跟条件**：`@改变 敌方血量 -伤害 | 命中 >= 40`（先掷 `命中`，再决定打没打中）——
  这是这套语法里替代 if 的写法，条件不满足就整条跳过。
- 数组元素写入时会把 `{数值}` 结算成当时的数字，所以"战报"记的是当时的结果，不会事后变。
- 行动 / 回合里没写正文时，面板保留上一段文字，不会突然变空白。
- 战斗中的数值和数组都写进 `存档.txt`，关掉再打开能**接着打**（位置还停在这个节点）。

上面「封装节点」那一节里的整段代码就是能直接跑的战斗骨架：血条、背包、道具、
掷骰检定（`@骰 伤害 = 1d6+2`）、回合反击、战报日志、胜负两种出口都是那几行的组合。
想加技能就往 `@行动` 后面再抄一段，想加敌人就多写几个数值和血条。

#### 不是只能做战斗

`@回合` 是**可选的**——不写它，封装节点就只是一个"按钮都在本节点里执行的小界面"。
商店、考试、背包管理、组队界面……都是同一个机制：

- **商店**：`@显示 钱` + `@显示 背包 列表`，`@行动 买面包（3 块）| 钱 >= 3` → `@改变 钱 -3` / `@加 背包 面包`；
  钱不够时按钮自动消失。
- **答题**：一题一个节点，选项用 `>`，用 `@改变 得分 +1` 记分，最后按得分跳不同结局。
- **背包 / 状态**：用 `@按键 我的背包 -> 物品栏` 打开信息窗，里面用 `{背包}`、`{钱}` 实时显示。

同一套写法换个壳就是商店：`@显示 钱` + `@行动 买面包（3 块）| 钱 >= 3`，里面写
`@改变 钱 -3`、`@加 背包 面包`，最后用 `-> 离开商店` 出门。

### 功能按键 + 信息展示窗（`@按键` / `@信息`）

节点上方可以放一排小功能键，点了**要么展开一个信息窗，要么跳到指定节点**：

```
@信息 物品栏                ← 写在节点外面 = 全篇通用；写在节点里 = 只有这个节点能用
身上带着：{背包}
钱：{钱} 块

:: 杂货铺
@按键 我的背包 -> 物品栏     ← 打开信息窗
@按键 去考试 -> 考试         ← 跳到节点（和选项一样，会记进流程图）
```

信息窗的样子：居中一块面板，标题青色，正文按当前数值实时展开（背包、血量、笔记都能往里放），
内容长了可以用滚轮翻页；**点一下、按 Esc / 空格都能关掉**，关掉后故事还在原地。

注意：

- `@信息` 里只放文字（写 `@改变`/`@骰`/数组操作会被提示，它只用来展示）；
- `@按键` 的目标先按"本节点的信息窗 → 故事级信息窗 → 节点名"的顺序找，找不到会在问题清单里报出来；
- 功能键写在节点正文里（`@行动` 里面不行）。

### 骰子 / 检定（跑团风）

内置了骰子，写 `NdM` 就是"掷 N 个 M 面骰取和"（`d100` 等于 `1d100`）：

| 写法 | 作用 |
| --- | --- |
| `@数值 力量 = 3d6` | 初值也掷出来（开局面板：用骰子建属性） |
| `@骰 骰点 = 1d100` | **进这个节点时掷骰**，结果写进数值 |
| `@骰 力气 = 3d6, 敏捷 = 3d6, 意志 = 3d6` | 一句话掷多个值 |
| `@骰 伤害 = 2d6+1` | 多骰求和再加常数（`2d6-1d4+3` 这种也行） |
| `@改变 精神值 -1d6` | 效果里也能用骰子（随机掉血） |
| `> 硬闯 -> 门后 \| 骰点 <= 60` | **检定**：掷骰和固定值比 |
| `> 硬闯 -> 门后 \| 骰点 <= 力量` | **检定**：掷骰和另一个数值比 |
| 正文里写 `{骰点}` | 显示时替换成当前值，比如「你掷出了 {骰点}」 |

一个完整的检定节点：

```
@数值 力量 = 3d6

:: 门口
@摘要 门口：要不要硬闯
@骰 骰点 = 1d100
你把肩膀抵在门上。这一掷是 {骰点}（你的力量是 {力量}）。
> 硬闯 -> 门后 | 骰点 <= 60
> 用蛮力硬顶 -> 门后 | 骰点 <= 力量
> 算了，回去 -> 放弃

:: 门后
@骰 伤害 = 2d6+1
门开了，你擦破了手，掉了 {伤害} 点血。
@结局 1 进了门 | 骰子是这么说的。
```

- 掷出来的值只有在节点的 @显示 里写上才会露出来（写在 @显示 里会亮一下）；
- **每次真的走进这个节点都会重掷**（所以"回头再试一次"是有效的），
  但从流程图回溯过去时不会重掷，按存档里那次的快照复原；
- 骰子结果会写进存档，关掉再打开还是那个数。

其他没加指令的普通行都是正文，一行就是一段，太长会自动折行（中文按字断行，英文数字尽量不拆词）。

最小能跑的档案：

```
@标题 我的故事
@开始 开场

:: 开场
这里写开场白。
> 选项一 -> 甲
> 选项二 -> 乙

:: 甲
你选了甲。
@结局 1 结局名 | 收尾的一句话。

:: 乙
你选了乙。没有选项也没有箭头时，会自动显示「再玩一次 / 选择其他档案 / 退出」。
```

要加分支，就再挂一个 `:: 新节点`，把选项箭头指过去——想加多深就加多深，不需要改代码。

## 图片规则

1. 一个故事对应一个文件夹：`images\<档案文件名>\`。比如 `stories\十月三日.txt` 对应 `images\十月三日\`。
2. 文件名用数字：`1.png`、`2.png`……剧本里 `@图片 1` 就是它；`01.png` 也算 1 号。
3. 图片会**一直保留到下一次改动**，可以当背景用；想收掉就写 `@图片 0`。
4. 找不到图片时，画面里会直接写出缺哪张、该放到哪个路径。

### 不是 png 的图片会自动转换

直接把 jpg / bmp / gif / tif 丢进图片文件夹就行，**不用手动转换**：
程序在每次检测图片文件夹时（启动、进列表、按 `F5` 重载）会把它们转成同名 `.png`，
原图挪到同目录的 `_原图\` 里，不会删掉。转换完标题下面会有一行青色提示告诉你转了几张。

所以这些写法都等价：

```
images\十月三日\3.jpg   →  自动变成 3.png
images\十月三日\3.png   →  直接用
images\十月三日\03.jpg  →  也是 3 号，转成 03.png
```

少数情况会转不了，卡片右侧会写「图片 N 张（其中 M 张不是 png）」：
格式比较新（webp / heic 这类 GDI+ 不认识的）、同号已经有同名 png、
或者文件名不是数字（非数字命名的图程序本来就不读）。这些用画图、PS 之类的另存成 png 即可。
文件夹里的 `说明.txt` 这种非图片文件会被完全忽略，不影响计数。

如果不想开程序转，`tools\图片转PNG.ps1` 是同一个功能的命令行版：

```powershell
powershell -ExecutionPolicy Bypass -File tools\图片转PNG.ps1                          # 全部档案
powershell -ExecutionPolicy Bypass -File tools\图片转PNG.ps1 -Archive 十月三日
powershell -ExecutionPolicy Bypass -File tools\图片转PNG.ps1 -Check                   # 只看不转
```

| 剧情界面 | 文字逐字浮现；鼠标点按钮，或用数字键选"屏幕上第几个按钮"（选项 / 继续 / 结束按钮都算） |
| 空格 / 点空白处 | 正在打字时＝跳过动画；已经打完＝往下翻一页 |
| 滚轮 / 拖动右侧滚动条 | 上下滚动剧情（文字超过一屏时才会出现滚动条） |
| `PageUp` `PageDown` `Home` `End` `↑` `↓` | 键盘滚动 |
| `Tab` / 右下角「流程图 Tab」 | **打开 / 关闭流程图**（回溯、看进度） |
| 右下角「重开」 | 当前故事从头开始（流程图里走过的记录保留） |
| 右下角「档案列表」 | 回到选故事界面 |
| 档案列表里每张卡右下角的「删存档」 | 删掉这个档案的全部存档（会弹窗确认，故事和图片不受影响） |

游戏界面里**没有**打开文件夹、编辑剧本这类开发用的按钮——玩家看到的就是玩的部分。
下面这些是给你（作者）自己用的，界面上不显示：

| 作者小抄 | 说明 |
| --- | --- |
| `F5` | 重载剧本：改完文本按一下立刻生效 |
| `存档.txt` | 就在 exe 旁边，游玩进度都在里面，删掉＝全部从头再来 |
| `stories\` / `images\` | 剧本和图片的位置（打包时会被塞进 exe） |
| `<档案名>.issues.log` | 剧本有问题时写在 stories 目录里的清单 |

### 文字很长的时候

一屏放不下的节点不会再把尾部切掉了：

- 右侧出现滚动条，滑块长度表示可视区域占全文的比例；
- 打字机往下写的时候，画面会**自动跟着往下滚**，最新出现的那行一直留在可视区域；
- 一旦你自己滚过（滚轮、拖动滑块、按翻页键），自动跟随就停，交给你自己控制；
- 觉得打得慢就按空格全部显示出来，再慢慢翻；
- 文字特别多的节点，打字速度会自动加快（最多 8 秒左右浮现完），不用干等。

## 存档（全自动的）

**你什么都不用做**：每选一次、每走一步，程序都会自动把进度写进 exe 旁边的 `存档.txt`——
没有就创建，有就更新（就在 exe 旁边，想自己看直接开那个文件就行）。

存档里记着这些：

| 记的内容 | 长什么样 |
| --- | --- |
| 打过哪些故事 | `story 十月三日 \| ...` |
| 解锁了哪些结局 | `endings 1,3` |
| 现在在哪个故事、哪个节点、数值多少 | `current 门后 \| vars 精神值=65,清醒度=2` |
| 每个节点上次到达时的数值 | `node 十月三日 \| 楼道 \| vars 精神=75,天数=2` |
| 走过哪些分支（流程图的解锁情况） | `edge 十月三日 \| 楼道 -> 宿舍` |
| 每次正常进入某节点的记录（流程图叠卡用） | `enter 十月三日 \| 宿舍 \| n 2 \| from 楼道 \| vars 精神=55,天数=1` |

于是：**关掉游戏再打开，选同一个故事会直接回到上次的节点，数值一起复原**；
列表页那个故事右边也会写「▶ 接着上次玩」和上次的节点名。

想从头再来，删掉 `存档.txt` 就行。它是纯文本，看得懂就随便改。

## 流程图（Tab）

故事界面按 `Tab`（或点右下角「流程图 Tab」）打开——这是按剧本自动生成的路线图：

- **只画你走过的节点**，每张卡片显示 `@摘要` 和**上次来到这里时的数值**；
- 你当前所在的节点有青色高亮和 `▸`；
- 走过的分支画实线；**按当前数值能走的下一步**画青色虚线，指向还没解锁的节点时会显示一张
  「？未解锁」的虚线卡，上面写着那个选项的文字；
- **点任意一个走过的节点就能回溯过去**，数值也回到当时那一份——想试别的分支就用它；
- **同一个节点被正常剧情走进过好几次时，卡片会画成叠起来的一叠**，右下角写 `×4` 这样的次数；
  鼠标停上去，叠着的几张会**微微散开**；
- 点这种叠卡不会直接跳转，而是**摊成一排**：整屏被黑色半透明盖住，原先的流程图暂时不能点，
  每一张卡下面写着「第几次进入」「从哪个节点来」和这个节点界面上会显示的那几个数值
  （放不下就用 `…` 截断）。点其中一张就**回到那一次进入时的状态**；按 `Esc`（或直接选一张）回到流程图。
- 已经走过一次的分支会**固定留在图上**：哪怕后来数值变了走了别的路，之前解锁的节点也不会消失；
  只有当你用不同数值再次到达那个岔口，才会解锁并显示出另一条支线；
- 滚轮上下、`Shift+滚轮` 左右、拖滚动条都能移动；再按 `Tab` 或 `Esc` 回到故事。

流程图的所有解锁状态都在 `存档.txt` 里，所以关掉再开也还在。

每次"从正常剧情走进某个节点"都会记一笔（回溯点进去的不算），每个节点最多留最近 12 次，
更早的会被挤掉——界面上也摊不下更多。老存档没有这些记录，读进来照样能玩，
只是那些节点要等你再正常走进去才会开始叠。

## 打包发给别人

一句话：**双击 `tools\生成安装包.cmd`**，就会在 `发布\` 里生成一个带版本号的单文件 exe，
比如 `愚见者的故事书-v1.2.exe`。把这个 exe 发给别人，对方双击就能玩到你现在写的全部剧本和图片——不需要装任何东西。

它是怎么工作的：`发布\` 里那个 exe 是「启动器 + 你的游戏内容」拼起来的单个文件，
对方运行时它会先解包到 `%LOCALAPPDATA%\愚见者的故事书\`，然后启动游戏。
同一台机器第二次以后不会再解包（内容没变就不覆盖，所以对方自己改的剧本不会被冲掉）。

### 版本号怎么涨

版本号是三段式 `v大.中.小`，每打包一次就是一个新版本，同时在 `版本日志.txt` 里追加一行：

| 情况 | 涨哪一位 | 例子 |
| --- | --- | --- |
| **剧本有增减**（加了新故事，或者删了故事） | **中版本**：中号 +1，小号归零 | v0.1.2 → **v0.2.0** |
| 其它一切改动（**包括改代码 / 引擎逻辑**、剧情文字、图片） | **小版本**：小号 +1 | v0.1.2 → **v0.1.3** |
| **大版本**：不自动涨，**由你自己决定** | 改 `版本日志.txt` 里那行「大版本 0」 | v0.2.0 →（改成 1 后）**v1.0.0** |

测试阶段大版本就一直留 `0`。你哪天觉得该算正式的大版本了，把那一行改成 `1`，
下次打包就会得到 `v1.0.0`（中号小号重置）。

日志长这样，看一眼就知道每个版本里有什么：

```
v0.0.1 | 2026-10-16 12:05 | 小版本（代码 / 引擎有改动） | 剧本 4 · 图片 13 | … | 代码 a1b2c3d4e5-f6a7b8c9d0 | 内容 1122334455
v0.1.0 | 2026-10-17 11:02 | 中版本（新增剧本：雪夜旅馆） | 剧本 5 · 图片 17 | … | 代码 a1b2c3d4e5-f6a7b8c9d0 | 内容 6677889900
```

最后两列是代码指纹和内容指纹，只是用来在日志里注明"这版动了什么"，不参与版本号怎么涨。

打包时还会写一个 `版本.txt`（第一行是版本号），程序会读它，
所以收到包的人在**窗口标题和档案列表页**都能看到自己拿到的是哪一版，例如 `v1.2`。

命令行的用法：

```powershell
# 重新编译 + 打包（推荐，保证包是最新的）
powershell -ExecutionPolicy Bypass -File tools\pack_release.ps1 -Build

# 只用现有 exe 打包，不重新编译
powershell -ExecutionPolicy Bypass -File tools\pack_release.ps1

# 换输出目录 / 自己指定文件名（指定了名字就不再加版本号后缀）
powershell -ExecutionPolicy Bypass -File tools\pack_release.ps1 -OutDir D:\
powershell -ExecutionPolicy Bypass -File tools\pack_release.ps1 -Name 给朋友的.exe

# 不带图片，只发文字版
powershell -ExecutionPolicy Bypass -File tools\pack_release.ps1 -NoImages
```

VS Code 里也有对应的任务：`打包成一个 exe（发给别人）`。

打包时会自动做这几件事：重新编译（加 `-static`，见下）、收集 `stories\*.txt`、
收集 `images\*` 里的图片（跳过 `_原图\` 备份）、把 `README.md` 和 `版本.txt` 一起放进去、
往 `版本日志.txt` 追加一行，最后拼成一个 exe 并报告版本、体积和剧本 / 图片数量。

## 剧本写错了怎么办

程序会把问题找出来：

- 选档案界面：卡片右侧显示 `⚠ N 处问题`；
- 剧情界面：标题下面一行橙色文字显示第一条问题；
- 完整清单写到 `stories\<档案名>.issues.log`，改好剧本按 `F5` 会重新生成。

检查项包括：选项 / 箭头指向的节点不存在、节点名重复、`@图片` 编号不是数字、
看不懂的 `@指令`、节点既没有选项也没有箭头（玩家会卡住）、
条件 / 效果里的数值没有用 `@数值` 声明（会自动按 0 处理并提醒）、
`->` 全是带条件的却没写兜底、节点没写 `@摘要`。

## 编译

需要支持 C++17 的编译器（MinGW-w64 就行），只依赖系统自带库：

```bash
g++ -std=c++17 -mwindows -O2 -static -o 愚见者的故事书.exe main.cpp -lgdi32 -luser32 -lgdiplus -lole32 -lshell32 -lmsimg32
```

`-mwindows` 表示生成 GUI 程序，运行时不会带一个黑色控制台窗口。
`-static` 很关键：它把 C++ 运行库一起编进 exe，否则拿到没装 MinGW 的电脑上会报缺
`libstdc++-6.dll` / `libgcc_s_seh-1.dll`。加了 `-static` 之后，exe 只依赖 Windows 自带的系统 DLL。
VS Code 里按 `Ctrl+Shift+B` 也行（`.vscode\tasks.json` 已配好）。

想再玩最初那版终端游戏：

```bash
g++ -std=c++17 -O2 -o main.exe terminal_version.cpp
```

## 界面上的小细节

- 深色夜色渐变底，青色是强调色，结局和结尾语用暖黄色；标题会自动显示成当前故事的名字。
- 文字块在面板里垂直居中；小窗模式上图下文，全屏模式整窗铺满图片、文字放在半透明底框里。
- 选项按钮固定预留三个位置，三个变两个时界面不跳；选项多了自动压缩按钮高度（最多 8 个）。
- 按屏幕 DPI 自动缩放；窗口比桌面还高时会自动收一点比例，保证整窗可见。
- 图片是**先读进内存再交给 GDI+** 渲染的，程序不会锁住图片文件——游戏开着也能直接换图，按 `F5` 立刻看到。
